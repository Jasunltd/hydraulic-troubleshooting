# A3 — Hydraulic Troubleshooting: Interpretable Signal Discovery

## Background

Unplanned downtime often creates pressure to diagnose quickly from multiple process signals. A fast but poorly grounded diagnosis can increase repeat work, component swapping, and cognitive load. This clean-room case asks whether public experimental hydraulic data can support an interpretable evidence-narrowing workflow before using AI or a black-box classifier.

## Current condition

Public source:
- 2,205 repeated 60-second cycles;
- 17 sensor streams;
- four deliberately varied component conditions;
- source-provided static/stable flag.

Measured audit:
- 1,449 stable cycles;
- 756 source-flagged non-static cycles;
- all 144 possible stable component-state combinations represented;
- 10–19 stable repetitions per combination;
- 725 discovery and 724 verification cycles after deterministic stratified splitting.

The first whole-cycle analysis failed to produce adequate evidence for all fault families. Time-localized matched comparisons then produced specific signatures for cooler and valve, while pump and accumulator remained materially ambiguous.

## Problem statement

A high-magnitude sensor change is not automatically a component-specific fault signal. The engineering problem is to distinguish **repeatable evidence that narrows a hypothesis** from cross-sensitive measurements that could drive premature root-cause claims.

## Target condition

Demonstrate, on independent evidence, that a transparent stability-gated troubleshooting sequence:
- reduces the number of plausible component families requiring follow-up;
- preserves an explicit "inconclusive/escalate" state;
- does not increase false isolation;
- does not trigger automatic equipment action.

No numeric operational target is claimed until an independent validation population is selected.

## Cause analysis

Observed contributors to diagnostic ambiguity:
1. non-static process state can contaminate stable-state comparisons;
2. whole-cycle averaging hides time-localized valve/switching behavior;
3. hydraulic variables respond to multiple component conditions;
4. large effect magnitude alone can be cross-sensitive;
5. a small fully healthy reference population is insufficient for a defensible production SPC claim.

## Countermeasures / experiments

Current proposal:
- state-validity gate;
- time-localized deterministic signal extraction;
- component-specific branches only where specificity is verified;
- multi-signal/physical confirmation for pump and accumulator;
- explicit escalation for disagreement.

Next experiment:
- freeze the staged rule;
- apply it to a semantically compatible independent public dataset or independently specified simulation;
- measure candidate-count reduction, false-isolation behavior, and diagnostic-time proxy.

## Follow-up / control

Not implemented.

Future control requires:
- process owner;
- sensor-health checks;
- documented reaction plan;
- retained evidence for every diagnostic branch;
- periodic false-isolation review;
- sustainment horizon before any realized-benefit claim.
